## 1. What this feature is

The thesis demo becomes a **real running system**: one FastAPI process serves the webhook, runs the real pipeline in the background (real models, D-9), streams every stage live over WebSocket, and hands the §5.4 gate to a human operator. One incident at a time: pick a fixture (or POST any valid alert), watch the machine think, approve or reject at the gate, and see a real scoped GitHub rollback execute on approve (D-10). A proper React/Vite/Tailwind console is the frontend; the film (feature 6) stays mounted as the history tab.

## 3. Design references (D-11)

- **Voice:** driver-level `astream(stream_mode="updates")`; chunk → event mapping: classify→classified, escalate→escalating, evidence→tool_call, rca→plan (or manual_review), __interrupt__→gate_open, rollback→rollback, terminal→done. Zero changes to `state_machine.py` (empirically probed on LangGraph 1.2.11).
- **Human gate:** GateAwaiter asyncio-Future registry; the WS/POST decision handler resolves the future (same `_route_decision` validation as dashboard, imported), the driver owns the phase-2 resume → no two tasks resume one checkpoint.
- **Serve process:** one FastAPI app hosting webhook + `/api/fixtures` + `/api/status` + `/ws` + `/film` (player mount) + `frontend/dist` static.
- **Frontend:** React 19 + Vite + Tailwind v4 (`@tailwindcss/vite`, CSS `@import "tailwindcss"`), TypeScript; dev via Vite proxy (`ws:true`), prod via FastAPI static.
- **Operations (verified live 2026-09-24):** `scripts/run_console.py --smoke` runs the no-quota rehearsal mode (zero-token fakes, flushes the queue + seen-set at startup — console-only sandbox); real models are the default when env is configured. The picker's fire button posts `?force=1` (bypasses the dedupe seen-set — console rehearsal only; plain POSTs stay dedupe-by-default, FR-1). Re-firing the same incident opens a **fresh gate** (D-11 postmortem #1/reset). The `/film` history player's API lives under the mount (`/film/api/...`) — its embedded JS uses relative fetches (postmortem #3). An idle worker is silent: the natural `brpop` timeout logs nothing (postmortem #4). **Queue honesty (postmortem #5):** firing while a gate is parked is *queued, not broken* — the picker footer answers "ran or queued?" at the moment of the fire (`queued c-02 — c-01 parked at the gate; decide it first`) and the queued run's timeline carries a persistent `QUEUED behind <gate>` banner until its run starts. Sequencing stays by-design (D-11); the console no longer reads as a dead machine when blocked by the human gate.
- **D-12 operator surface + transparency batches (design 2026-09-28, verified live same day):** the operator console is a professional light theme (canvas `#f4f5f7`, white cards, near-black text, seeded AA-ish status colors; mono only for ids/JSON/timestamps; 13px base — dark terminal revoked for the operator, film player stays cinematic). **Batch A — information density:** every stage row expands to a full per-type detail panel — evidence cards with tool chips + raw JSON, plan with confidence bar and attributed steps, decision/rollback/done detail — plus run-state pills (PROCESSING / AWAITING DECISION / RESOLVED / REJECTED / …), durations on every summary line, and a QUEUED banner. **Batch B1 — live enriched milestones (backend, no new event types):** the driver stamps every event with `mode` (smoke vs real), `model_env` (the configured SLM/frontier model per stage), and `stage_duration_ms` (wall-clock between astream chunks; the clock restarts at the gate resume so the rollback stage never inherits the operator's decision wait); evidence records carry their origin tool (`_tool` = `fetch_service_logs` / `query_prometheus_metrics`) in both real (`app/evidence.py`) and smoke (`app/benchmark.py`) gatherers; the header shows a SMOKE/REAL chip from `/api/status.mode`. **Batch C — the gate feels real:** clicking approve/reject renders an optimistic "Decision recorded — approve/reject (EXECUTING/CLOSING)" confirmation the instant the click lands, and the card stays mounted until the terminal; reject completes fast and honestly ("no action was taken and no tool ran"). **Batch D:** the film rides the richer records automatically — verified mounted + serving after restart.

## 4. Acceptance

Given the serve app running with real models and Redis up:

1. `GET /api/fixtures` returns the synthetic catalog (alert fields only — no ground truth leaks to the operator).
2. POSTing a fixture's alert to `/webhook/incident` enqueues it and publishes an `ingest` event.
3. The pipeline picks it up and the WebSocket receives, in order: `classified` → (`escalating` when the D-4 rule fires) → `tool_call` → `plan` → `gate_open` (carrying the plan).
4. The console shows the gate; clicking **approve** resumes the parked graph and produces `rollback` (real scoped GitHub tag when env is configured, else a loud error rendered honestly) then `done(resolved)`. Clicking **reject** produces `done(rejected)` with **no** rollback/network call (NG-1).
5. A second decision on the same incident is refused: `already_decided`, first wins (§5.4).
6. A model-down run degrades honestly: `manual_review` event + `done(manual_review)` with the recorded reason; the console renders a failed run, no gate is shown.
7. The film is still reachable at `/film/` (history tab).
8. No stage event is ever emitted for an alert the operator never approved — the `rollback`/network path is unreachable pre-approval.
9. **B1 stamps:** every milestone event carries `mode`, and classified/plan/tool_call also carry `stage_duration_ms` (≥0); classified carries `model_env` (the env-configured SLM name), plan carries the frontier name; post-gate stages restart the clock at resume (regression-tested); `tool_call` evidence rows each carry `_tool`; `/api/status` exposes `mode`.
10. **Batch A:** each timeline stage row expands (click) to its per-type detail with all carried evidence/plan fields + raw JSON; an evidence stage renders tool chips from `_tool` and a record count; run-state pill + per-stage durations render from the stamps above (browser-verified live).
11. **Batch C:** clicking approve/reject immediately renders the decision-recorded confirmation (no dead button); the card persists until the terminal; reject never fires a tool (NG-1).
12. **Theme:** the operator surface is the D-12 light UI (verified via computed styles — canvas `rgb(244,245,247)`, near-black text, white cards); the film player is unchanged.
13. **Watchable rehearsal (D-13):** a `--smoke` fire visibly streams — stages arrive one at a time (~0.5 s classify, ~0.9 s evidence, ~1.4 s rca, ~0.5 s rollback; regression-tested that the console's graph is paced while benchmark/test fakes stay instant and `NEXUSOPS_SMOKE_PACE=0` restores instant mode). Pacing never fabricates data: labels stay SMOKE, evidence/plan stay deterministic fixtures, and `stage_duration_ms` truthfully measures the paced stream's real wall-clock.
14. **Real-mode transient retry (D-13 addendum):** the console's real graph (`run_console._real_make_graph`) wraps classify/rca in the tested `_retry_model` (2 attempts, 1 s backoff) so an intermittent Gemini free-tier `503 high demand` cannot silently degrade a live incident to `manual_review`; hard errors (bad key, quota exhaustion, broken contract) still surface immediately and honestly, and the final attempt raises so latency includes real retries (regression-tested via injected flaky model fn).
15. **Live progress + explicit calls (T-7.10):** the console's pipeline stepper shows six canonical steps (Ingest → Classify → Evidence → Plan → Gate → Resolve) with the active step pulsing and a live elapsed ticker that runs on the client-observed `_arrived_ms` (WS receipt wall-clock — an observation, never a server timing claim); completed steps render the server's honest `stage_duration_ms`. The evidence stage renders one visible function-call row per tool with the returned record count (function calls explicit, records one click deeper). The incident record panel consolidates alert / classification (model + duration) / evidence-by-tool / plan (hypothesis, confidence, model, steps) / gate (wait + decision + actor) / rollback / terminal (state + resolve total + reason) / raw-JSON toggle. An aborted run marks the failing step `!` and dashes every step after it — a run that never opened a gate must never render a green gate check (regression-guarded by the step-state derivation, not a test).
16. **RCA-as-operator-config (T-7.11):** with `NEXUSOPS_RCA_MODEL=slm` (or `run_console --slm-rca`), the `plan` event's `model_env`, the `escalating` event's `depth_model`, and `/api/status.rca_model` all name the SLM — the consuming node and the stamp read the same env, so a stamp can never name a model that didn't write the plan (regression-tested at both the state-machine and serve-driver level). Default without the env keeps D-4: the frontier deep-dives escalated incidents, and `rca_model` reports the frontier.
17. **Typed, never-empty failure reasons (T-7.12 / D-15):** every model-call failure the console can see is a classified, non-empty sentence `stage failed (kind): detail` with `kind ∈ transport | http | quota | schema | empty | config` — a transport flap reads `SLM classify failed (transport): LLM transport failure for gemini-3.5-flash-lite: ReadTimeout` (transient — retry/skip), quota exhaustion reads `…failed (quota): …` (terminal — never retried), and a cause whose `str()` is empty still names the exception class (never a bare "model error"). The `manual_review` event carries `reason` + `stage`; `done` carries `manual_review_reason`. Regression-guarded: empty-str transport cause reproduces the exact live bug, quota-429 is `kind=quota` + non-retryable, schema violations are `kind=schema`.
18. **Operator detail batch (T-7.13 / D-16):** (a) the `ingest` event carries the FULL alert envelope — `occurred_at`, `status_code`, `summary` (1–2 sentence problem prose), `context` (sender-provided structured facts), `error_type`, `metadata` — so the incident phase shows what was received, and `/api/fixtures` exposes `status_code`/`summary`/`context` (still ground-truth-free: `expected`/`ground` never leave); (b) the plan carries a required `reasoning` WHY-chain (why this hypothesis + per-evidence support) rendered at the gate and in the incident record, with the cited evidence as chips; (c) the §5.4 frame accepts an OPTIONAL operator `reason` that rides the resume body and the `decision` event (absent stays absent — prose never gates execution; a blank string is a loud socket error); (d) `tool_call.evidence` raw records render INLINE in the incident record, never behind a click. **Live proof (2026-09-28, real console `--slm-rca`, c-03 reject cycle):** ingest carried summary/context/occurred/status; the SLM's `plan.reasoning` cited evidence items 1–12 of 32 raw MCP records; the reject-with-reason frame returned `decision.reason` verbatim and terminated `rejected` with no rollback (NG-1).

## 5. Out of scope (B roadmap, recorded for later)

- Multi-incident concurrency (sequential loop by design for the demo).
- Auth/production hardening (single operator, single API key accepted).
- Real monitoring connectors (Prometheus/PagerDuty) — the webhook contract already matches them; wiring them is a config+adapter task.
- Revert-commit rollback (D-10 already records this as the heavier B upgrade).
